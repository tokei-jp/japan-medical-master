# 前提・仮定事項（長野県パイロット: 移動負荷係数モデル）

## 0. データ取得・実ファイルレイアウトについて

以前のセッションではネットワークegressの制約により2つのExcelファイルを
実際にダウンロードできなかったが、本セッションでは
`python scripts/fetch_sources.py` で両ファイルを取得・確認できた。
実ファイルは当初の想定と異なる形式だったため、`scripts/build_geo_coefficient.py`
を実データに合わせて修正済み：

- `habitable_area.xlsx`（統計でみる市区町村のすがた 表B）は通常の
  ヘッダー付き表（6行目がヘッダー、列見出しはセル内に改行や半角ｺｰﾄﾞ表記を
  含む）。ヘッダー検出・列名一致はNFKC正規化＋改行除去した上で行うように
  修正した。
- `medical_zone_mapping.xlsx`（二次医療圏－市区町村対応表）は
  市区町村コード列を持たない、都道府県ブロック単位の印刷用グリッド形式
  （1列目=二次医療圏コード、2列目=圏域名、3列目以降＋継続行に市区町村名を
  複数列に渡って羅列）だった。そのため市区町村コードではなく
  正規化した市区町村名で突合している（`load_medical_zone_mapping` /
  `normalize_muni_name` 参照）。
- 出力CSV `data/output/nagano_secondary_medical_zone_geo_coefficient.csv`
  は実データで生成済み。長野県10二次医療圏・77市区町村すべてが突合でき、
  可住地面積の合計（3,248.97 km²）は表B記載の長野県総可住地面積
  （3,248.93 km²、集計時の丸め誤差の範囲内）とほぼ一致している。

## 1. benchmark（分母となる中央値）

`benchmark = median(spacing_i)` は長野県内の二次医療圏全体（想定10圏域）の
spacing の中央値を初期値として採用。将来的には全国345圏域展開時に
「都道府県内中央値」か「全国中央値」かを再検討する（要検証事項1）。

## 2. λ = 0.3、下限0.85、上限1.30

指示書に基づく初期値。実績訪問件数（Call数）等の実データが揃い次第、
回帰・感度分析でCalibrationする（要検証事項2・3）。

## 3. target_facility_count / simple_required_fte

指示書の通り、全圏域一律の仮の定数（10施設、3.0FTE）。
ユーザーが実データ（対象施設リスト、必要FTE試算）に差し替える前提。

## 4. 道路距離・移動時間

初期版では使用しない（可住地面積ベースの近似のみ）。

## 5. 市区町村コードの正規化

e-Statのファイルは全国地方公共団体コード（JIS、6桁でチェックディジット付き）
または5桁のいずれかで市区町村コードを持つことが多い。
`normalize_muni_code()` は数字以外を除去し、6桁以上ならチェックディジットを
落として先頭5桁を採用、5桁ならそのまま zero-fill する。実ファイルで
コード桁数が異なる場合はこの関数を調整すること。

## 6. 二次医療圏対応表の代替候補

指定の統計表（statInfId=000040224319）が古い/形式が合わない場合は
「患者調査 二次医療圏－市区町村対応表」（statInfId=000031348710 付近）を
代替候補として使う旨、指示書に記載あり。`scripts/fetch_sources.py` の
`SOURCES` にコメントとして残してある。実際にどちらを使うかはファイル内容
確認後に判断すること。
