# 前提・仮定事項（長野県パイロット: 移動負荷係数モデル）

## 0. 実行環境の制約（重要）

このリポジトリを構築したセッションのネットワークegressは e-stat.go.jp を含む
ほぼ全ての外部ドメインへのアクセスがポリシーでブロックされており、
Step 1 で指定された2つのExcelファイルを実際にダウンロード・中身確認する
ことができなかった。そのため：

- `scripts/fetch_sources.py` / `scripts/build_geo_coefficient.py` は
  実データなしで書かれており、e-Statの実シートレイアウト（ヘッダー行位置、
  列名の正確な表記）を確認できていない。
- ヘッダー検出はキーワード一致による防御的な実装にしてあるが、
  実ファイルを開いた時に `LookupError` が出た場合は各スクリプト冒頭の
  `*_KEYWORDS` リストを実際の列見出しに合わせて調整する必要がある。
- 出力CSVはこのリポジトリには含まれていない（捏造データを出力しないため）。
  ネットワークアクセスがある環境で
  `pip install -r requirements.txt && python scripts/fetch_sources.py && python scripts/build_geo_coefficient.py`
  を実行して生成すること。

## 1. benchmark（分母となる中央値）

`benchmark = median(spacing_i)` は長野県内の二次医療圏全体（想定10圏域）の
spacing の中央値を初期値として採用。将来的には全国345圏域展開時に
「都道府県内中央値」か「全国中央値」かを再検討する（要検証事項1）。

## 2. λ = 0.3、下限0.85、上限1.30

指示書に基づく初期値。実績訪問件数（Call数）等の実データが揃い次第、
回帰・感度分析でCalibrationする（要検証事項2・3）。

## 3. target_facility_count / simple_required_fte

指示書の通り、全圏域一律の仮の定数（10施設、3.0FTE）。
ユーザーが実データ（対象施設リスト、必要FTE試算）に差し替える前提。

## 4. 道路距離・移動時間

初期版では使用しない（可住地面積ベースの近似のみ）。

## 5. 市区町村コードの正規化

e-Statのファイルは全国地方公共団体コード（JIS、6桁でチェックディジット付き）
または5桁のいずれかで市区町村コードを持つことが多い。
`normalize_muni_code()` は数字以外を除去し、6桁以上ならチェックディジットを
落として先頭5桁を採用、5桁ならそのまま zero-fill する。実ファイルで
コード桁数が異なる場合はこの関数を調整すること。

## 6. 二次医療圏対応表の代替候補

指定の統計表（statInfId=000040224319）が古い/形式が合わない場合は
「患者調査 二次医療圏－市区町村対応表」（statInfId=000031348710 付近）を
代替候補として使う旨、指示書に記載あり。`scripts/fetch_sources.py` の
`SOURCES` にコメントとして残してある。実際にどちらを使うかはファイル内容
確認後に判断すること。
